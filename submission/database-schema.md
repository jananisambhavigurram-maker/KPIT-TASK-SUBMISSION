# Database Schema

## Database technology and schema management

AgileFlow uses SQLite through Prisma ORM. The datasource URL is read from DATABASE_URL; the supplied environment template uses file:./dev.db, which resolves relative to the Prisma schema location.

The schema is defined in prisma/schema.prisma. The repository does not contain a prisma/migrations directory. The documented setup command is prisma db push, which synchronizes the local schema without keeping a committed migration history. prisma/seed.ts resets and recreates demonstration data; it is not a non-destructive seed.

All primary IDs are String CUID values generated by Prisma. Created timestamps default to now where listed. updatedAt fields are maintained by Prisma.

## Enumerations

| Enum | Values | Used by |
|---|---|---|
| ProjectStatus | ACTIVE, COMPLETED, ARCHIVED | Project.status |
| WorkStatus | TODO, IN_PROGRESS, DONE | UserStory.status and Task.status |
| Priority | LOW, MEDIUM, HIGH | UserStory.priority and Task.priority |
| JobStatus | PENDING, PROCESSING, COMPLETED, FAILED | BackgroundJob.status |
| Role | ADMIN, MANAGER, MEMBER | User.role |

## Relationship diagram

~~~mermaid
erDiagram
  USER ||--o{ PROJECT_MEMBER : has
  PROJECT ||--o{ PROJECT_MEMBER : has
  PROJECT ||--o{ USER_STORY : contains
  USER_STORY ||--o{ TASK : contains
  USER o|--o{ TASK : assigned_to
  USER ||--o{ NOTIFICATION : receives
  PROJECT ||--o{ ACTIVITY : records
~~~

BackgroundJob is deliberately not shown with a relational link: its payload is a JSON string, and Notification.sourceJobId is a unique string rather than a declared foreign key. Activity.actorId is also an optional string and not a Prisma relation in the current schema.

## Hierarchy: Project to User Story to Task

~~~text
Project (id)
  1 └── many UserStory rows through UserStory.projectId
              1 └── many Task rows through Task.userStoryId
~~~

UserStory.projectId is required and references Project.id with onDelete: Cascade. Task.userStoryId is required and references UserStory.id with onDelete: Cascade. Deleting a project cascades to its stories and then to tasks through these relations.

## Models

### User

Purpose: application account, role holder, potential task assignee, notification recipient, and project member.

| Field | Type / nullability / default | Notes |
|---|---|---|
| id | String, primary key, CUID default | Internal account identifier. |
| name | String, required | User-visible name. |
| email | String, required, unique | Account login identifier. |
| passwordHash | String, required, default empty string | Stores a salted scrypt hash for created accounts. |
| sessionVersion | Int, required, default 0 | Included in signed tokens; incrementing it invalidates prior tokens. |
| role | Role, required, default MEMBER | ADMIN, MANAGER, or MEMBER. |
| createdAt | DateTime, required, default now | Creation timestamp. |

Relationships:

- assignedTasks: one user can be assigned many Task records through Task.assignedToId.
- notifications: one user receives many Notification records.
- memberships: one user has many ProjectMember records.

Constraints and delete behaviour:

- email has a unique constraint.
- Task.assignedTo uses onDelete: SetNull, so deleting a user unassigns tasks rather than deleting them.
- Notification.user uses onDelete: Cascade, so deleting a user deletes their notifications.
- ProjectMember.user uses onDelete: Cascade, so deleting a user removes membership records.

### Project

Purpose: top-level delivery container.

| Field | Type / nullability / default | Notes |
|---|---|---|
| id | String, primary key, CUID default | Internal project identifier. |
| key | String, required, unique | Human-readable code such as ECOM. |
| name | String, required | Project name. |
| description | String, required, default empty string | Project description. |
| status | ProjectStatus, required, default ACTIVE | Lifecycle state. |
| createdAt | DateTime, required, default now | Creation time. |
| updatedAt | DateTime, required, Prisma updatedAt | Updated automatically by Prisma. |

Relationships:

- stories: one project contains many UserStory records.
- activities: one project contains many Activity records.
- members: one project has many ProjectMember records.

Indexes and delete behaviour:

- index on status.
- deleting a project cascades to UserStory, Activity, and ProjectMember records.
- stories then cascade to their Task records.

### ProjectMember

Purpose: join model used to scope non-admin project access and validate valid task assignees.

| Field | Type / nullability / default | Notes |
|---|---|---|
| id | String, primary key, CUID default | Join-record identifier. |
| projectId | String, required | Foreign key to Project.id. |
| userId | String, required | Foreign key to User.id. |
| createdAt | DateTime, required, default now | Membership creation time. |

Constraints and indexes:

- composite unique constraint on projectId and userId prevents duplicate membership.
- index on userId supports finding a user's memberships.
- both foreign keys use onDelete: Cascade.

### UserStory

Purpose: a project-level delivery item containing tasks.

| Field | Type / nullability / default | Notes |
|---|---|---|
| id | String, primary key, CUID default | Internal story identifier. |
| projectId | String, required | Foreign key to Project.id. |
| key | String, required, unique | Human-readable story key such as ECOM-US-001. |
| title | String, required | Story title. |
| description | String, required, default empty string | Story description. |
| status | WorkStatus, required, default TODO | TODO, IN_PROGRESS, or DONE. |
| priority | Priority, required, default MEDIUM | LOW, MEDIUM, or HIGH. |
| createdAt | DateTime, required, default now | Creation time. |
| updatedAt | DateTime, required, Prisma updatedAt | Update time. |

Constraints, indexes, and delete behaviour:

- projectId references Project.id with onDelete: Cascade.
- key is unique globally, not merely within its project.
- indexes on projectId and status.
- deleting a story cascades to Task records.

### Task

Purpose: smallest trackable work item, optionally assigned to a user and optionally due on a date.

| Field | Type / nullability / default | Notes |
|---|---|---|
| id | String, primary key, CUID default | Internal task identifier. |
| userStoryId | String, required | Foreign key to UserStory.id. |
| key | String, required, unique | Human-readable task key such as ECOM-T-001. |
| title | String, required | Task title. |
| description | String, required, default empty string | Task description. |
| status | WorkStatus, required, default TODO | Workflow status. |
| priority | Priority, required, default MEDIUM | Task priority. |
| assignedToId | String, nullable | Foreign key to User.id, when assigned. |
| dueDate | DateTime, nullable | Optional due date. |
| createdAt | DateTime, required, default now | Creation time. |
| updatedAt | DateTime, required, Prisma updatedAt | Update time and assignment version source. |

Constraints, indexes, and delete behaviour:

- userStoryId references UserStory.id with onDelete: Cascade.
- assignedToId references User.id with onDelete: SetNull.
- key is globally unique.
- indexes on userStoryId, assignedToId, and composite status/priority.
- the API additionally requires an assignee to be a ProjectMember; that requirement is application logic, not a database foreign key.

### Notification

Purpose: persisted in-app notification, currently used by the assignment worker.

| Field | Type / nullability / default | Notes |
|---|---|---|
| id | String, primary key, CUID default | Notification identifier. |
| userId | String, required | Foreign key to User.id. |
| type | String, required | Current worker writes TASK_ASSIGNED. |
| message | String, required | Notification text. |
| sourceJobId | String, nullable, unique | Idempotency key for a background job. It is not a foreign key. |
| isRead | Boolean, required, default false | Read state. |
| createdAt | DateTime, required, default now | Creation time. |

Constraints, indexes, and delete behaviour:

- userId references User.id with onDelete: Cascade.
- sourceJobId unique constraint permits at most one notification per stored job ID.
- composite index on userId and isRead supports unread and per-user queries.

### BackgroundJob

Purpose: durable internal queue record. There is no direct API endpoint for this model.

| Field | Type / nullability / default | Notes |
|---|---|---|
| id | String, primary key, CUID default | Job identifier. |
| type | String, required | Current workflow uses TASK_ASSIGNED. |
| payload | String, required | JSON string with taskId, userId, and assignmentVersion. |
| status | JobStatus, required, default PENDING | PENDING, PROCESSING, COMPLETED, or FAILED. |
| attempts | Int, required, default 0 | Incremented when claimed. |
| maxAttempts | Int, required, default 3 | Failure threshold used by the worker. |
| lastError | String, nullable | Most recent processing/recovery error. |
| lockedAt | DateTime, nullable | Set when a worker claims a job. |
| runAfter | DateTime, required, default now | Earliest time the worker should process/retry it. |
| createdAt | DateTime, required, default now | Creation time. |
| updatedAt | DateTime, required, Prisma updatedAt | Update time. |

Indexes:

- composite index on status and runAfter supports selecting due pending jobs.

### Activity

Purpose: recent project activity feed. The API currently writes activity for project creation/update, story creation/update, task creation, and task status change.

| Field | Type / nullability / default | Notes |
|---|---|---|
| id | String, primary key, CUID default | Activity identifier. |
| projectId | String, required | Foreign key to Project.id. |
| actorId | String, nullable | Actor identifier string; no declared User relation/foreign key in the schema. |
| type | String, required | Event label such as PROJECT_CREATED or TASK_STATUS_CHANGED. |
| message | String, required | Display message. |
| createdAt | DateTime, required, default now | Creation time. |

Constraints, indexes, and delete behaviour:

- projectId references Project.id with onDelete: Cascade.
- composite index on projectId and createdAt supports the recent activity query.

## Seed data and backfill helper

prisma/seed.ts first deletes background jobs, notifications, activities, tasks, stories, projects, and users, then creates five demo accounts, two projects, memberships, stories, tasks, activity rows, and one notification. All seeded accounts use the password DemoPass123!.

prisma/backfill-keys.ts is a one-off local helper that reads existing projects, stories, and tasks and fills missing keys based on project names and creation order. It is not a migration system and is intended only for older local data.
